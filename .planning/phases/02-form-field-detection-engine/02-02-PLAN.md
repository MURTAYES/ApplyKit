# Plan 02-02: Native Field Setter, Fill Pipeline, and Content Script Integration

## Goal
Implement the framework-compatible native field setter, strict safety/non-overwrite guards (R1–R6), full fill engine orchestrator, and wire up the popup trigger and content script messaging.

## Must-Haves
- Reactive native prototype setter (`HTMLInputElement.prototype.value` / `HTMLTextAreaElement.prototype.value`) with bubbling `focus` -> `input` -> `change` -> `blur` event sequence (FILL-06).
- Strict non-overwrite protection (FILL-05): leaves non-empty user-typed fields (`value.trim() !== ''`) untouched.
- Safety filters (FILL-08, R1–R4): ignores submit buttons, button inputs, file upload inputs (`type="file"`), CAPTCHA fields, and declaration/terms checkboxes.
- Fill engine orchestrator that loads profile from `chrome.storage.local`, matches form fields, sets values, and produces a structured fill report `{ filledCount, skippedCount, unmatchedCount, details: [...] }`.
- Content script message handler (`entrypoints/content.ts`) that listens for `"TRIGGER_FILL"` message from popup, runs the fill engine, and returns telemetry.
- Popup UI update in `entrypoints/popup/App.tsx` to handle "Fill Form" click, show loading feedback, and display completion telemetry.
- 100% passing Vitest test suite.

## Tasks

### Task 1: Native Property Setter & Event Dispatcher (`src/engine/fieldSetter.ts`)
- Implement `setNativeValue(element: HTMLInputElement | HTMLTextAreaElement, value: string): void`:
  - Retrieve descriptor for `value` from prototype (`HTMLInputElement.prototype` or `HTMLTextAreaElement.prototype`).
  - Invoke `.set.call(element, value)`.
  - Dispatch sequence:
    1. `new Event('focus', { bubbles: true })`
    2. `new Event('input', { bubbles: true })`
    3. `new Event('change', { bubbles: true })`
    4. `new Event('blur', { bubbles: true })`
- Write unit tests in `tests/engine/fieldSetter.test.ts` verifying React/HTML event firing.

### Task 2: Safety & Overwrite Validator (`src/engine/safety.ts`)
- Implement `isEligibleForFill(element: HTMLElement): boolean`:
  - Exclude submit, button, reset, hidden, file, and checkbox/radio inputs (until Phase 3/4).
  - Exclude inputs inside CAPTCHA containers (`[class*="captcha" i]`, `[id*="captcha" i]`, `iframe`).
  - Exclude declaration/terms inputs (`[name*="declaration" i]`, `[id*="agree" i]`).
- Implement `isFieldEmpty(element: HTMLInputElement | HTMLTextAreaElement): boolean`:
  - Check if `value.trim() === ''` or is a common placeholder/default prompt (e.g. `-- Select --`).
- Write unit tests in `tests/engine/safety.test.ts`.

### Task 3: Fill Engine Orchestrator (`src/engine/fillEngine.ts`)
- Define `FillReport` and `FillDetail` types:
  ```ts
  export interface FillReport {
    filledCount: number;
    skippedCount: number;
    unmatchedCount: number;
    details: Array<{
      fieldName: string;
      profileKey?: string;
      status: 'filled' | 'skipped_empty_profile' | 'skipped_user_filled' | 'unmatched';
      section?: string;
    }>;
  }
  ```
- Implement `executeFill(profile: Profile, rootElement: Document | HTMLElement = document): FillReport`:
  - Query all candidate `<input>` and `<textarea>` elements within `rootElement`.
  - Filter with `isEligibleForFill`.
  - For each element:
    - If `!isFieldEmpty(el)`: record as `skipped_user_filled`.
    - Run `matchField(el)`.
    - If no match found: record as `unmatched`.
    - If matched: resolve value from `profile` using `profileKey` and section.
    - If profile value is empty: record as `skipped_empty_profile` (FILL-04).
    - If profile value exists: format value (strip ZWJ/ZWNJ, digit conversion for numbers) and call `setNativeValue(el, formattedValue)`; record as `filled`.
  - Return compiled `FillReport`.
- Write unit tests in `tests/engine/fillEngine.test.ts` with mock government application HTML form.

### Task 4: Content Script & Popup Integration (`entrypoints/content.ts`, `entrypoints/popup/App.tsx`)
- Update `entrypoints/content.ts`:
  - Register `chrome.runtime.onMessage.addListener` for action `"TRIGGER_FILL"`.
  - On message, call `loadProfile()`, run `executeFill(profile)`, and return `FillReport` via sendResponse.
- Update `entrypoints/popup/App.tsx`:
  - On "⚡ Fill Form" click:
    - Get active tab using `chrome.tabs.query({ active: true, currentWindow: true })`.
    - Send message `{ action: 'TRIGGER_FILL' }` to active tab.
    - Display result status (e.g., `✓ Filled N fields` or summary banner) using Pearson Specter Litt design palette.
- Write tests in `tests/entrypoints/popup.test.tsx` verifying fill button trigger flow.
